# 像素游戏：特效、人物动作、物品动效研究

研究日期：2026-11-09。方法：作者/开发者材料和公开源码的跨作品案例检查；没有运行这些游戏、执行用户测试或测量实际动画时序。静态截图与资源文件名不能证明动画帧数、速度、命中窗口。

## 阶段 A：检验前冻结的候选规则

本节先写入文件，再搜索/阅读检验作品 Noita。推导组：Dead Cells（Motion Twin）、Celeste / Celeste Classic（同一制作谱系，只计一组）、Shovel Knight / Dig（Yacht Club Games 与 Nitrome 制作谱系，不假称两个独立团队）。Noita 此时未纳入推导；后文记录保留/收窄/撤回。

### 特效初版

- F1：先标记输入、动作生效、命中与状态结束，再将特效绑定到相应事件；不能靠视觉播放结束推断玩法结果。
- F2：威胁、角色和结果确认优先；拥挤时减掉装饰粒子/全屏强调，并检查减效模式的信息完整性。
- F3：先做主要形状与起落阶段，再考虑补帧、细碎粒子和混合；手绘像素、3D 转像素可以采用不同管线。

### 人物动作初版

- A1：先做可辨认的关键姿态并匹配动作功能，再加中间帧；不把更多帧视为更好。
- A2：动画状态服从明确的玩法状态、进入/退出与中断规则；移动、跳跃、受击、拾取的混合需逐项检查。
- A3：检查角色轮廓、接地点、朝向和握持锚点；允许程序缩放与混合渲染，但输出须在目标画面检查。

### 物品动效初版

- I1：用物品生命周期规定等待、掉落、可拾取、尝试拾取、结算、消失；展示不是入账依据。
- I2：按功能区分悬浮/就绪、开启、拒绝、使用/装备；切换与取消后的视觉必须回到真实状态。
- I3：动态位移与实际拾取区域、实体物理分开声明；装饰动效不能无意改变可达性，也不能将真实危险物误归类为装饰。

## 阶段 B：独立作品检查

阶段 A 写入后，才检索和读取 Noita；随后补查 Rain World（人物动作的反例）与 One Step From Eden（事件特效的独立案例）。它们没有参与初版规则生成。以下是文献/代码层面的检验，不是盲测或玩家实验。

| 规则 | 独立检查所见 | 处理与证据强度 |
| --- | --- | --- |
| F1 | Noita 作者解释燃烧、液体、爆炸后的塌落会改变世界；One Step From Eden 作者将爆炸链触发于敌人被消灭。 | **保留并收窄**：事件可以来自模拟状态，不限于按钮/命中事件；视觉与玩法共享原因，不要求玩法必须脱离一切视觉模型。跨案例一致，架构实现仍是本文提案。 |
| F2 | Noita 的火焰/液体/碎块可能是危险或物理实体，删掉它们会改变信息或规则。 | **收窄**：“先减粒子”改成“先给每层标记功能，只减装饰层”；未验证少粒子一定更清晰。 |
| F3 | Noita 的动态由材料规则涌现，不能预先画好所有完整变化；One Step From Eden 把序列图与生成器结合。 | **收窄**：预制阶段适合一次性序列特效；模拟特效需验证材料转换与持续/停止条件。 |
| A1 | Rain World 作者访谈说明角色逐渐从传统/程序混合转向程序动画。 | **撤回普遍版本**；仅在姿态序列方案里保留“关键姿态先行”。程序方案先设身体约束、支撑点与输入响应。 |
| A2 | Rain World 的肢体随输入和模拟变化，并非所有表现都对应独立动画片段。 | **保留语义、收窄实现**：必须能说明行为与表现关系，但不强迫所有角色使用同一有限状态机。 |
| A3 | Rain World 将两块身体作为物理基础，肢体/尾巴另行表现；说明绘制轮廓与物理身体可以不同。 | **保留检查目的、撤回轮廓等于碰撞体的潜在推论**；没有证据证明某种锚点方案普遍最优。 |
| I1 | Noita 官方补丁处理宝箱掉落的确定性，并修复掉落输入冲突；这不是对“视觉结束就应入账”的支持。 | **保留为工程检查**：结算与表现的对应可复查。一次性结算/幂等是本文执行提案，案例未证明所有游戏都采用该结构。 |
| I2 | Noita 补丁修复喝药/丢弃的按键冲突；状态意图不能只靠同一个输入推断。 | **保留为待测设计**：至少区分意图、接受、拒绝、结果；未观察其悬停、装备动画视觉效果，不能标成美术效果已验证。 |
| I3 | Noita 官方材料与补丁说明刚体、灯具、家具具有真实物理/破坏状态，保存载入曾丢失变换与关节。 | **保留并明确分支**：装饰偏移、碰撞移动、可破坏实体三类分别处理；不能将所有物品动效改为纯贴图漂浮。 |

支持以上检查的原始材料：

- **H1** Petri Purho / Nolla Games（2019），[Noita 开发者访谈](https://80.lv/articles/noita-a-game-based-on-falling-sand-simulation)。读取材料、刚体、爆炸与法杖系统正文；这是开发者第一人称回答，图片/嵌入视频未逐帧检查。材料模拟是对“粒子只负责好看”的直接反例。

- **H3** Videocult / Akupara Games 开发者访谈（2025），[Rain World: The Watcher 程序设计](https://unity.com/blog/exploring-procedural-design-rain-world)。读取“Animating the slugcat”：两个身体块与程序肢体、传统/程序方案的演变。正文的营销形容词不当作效果测量。
- **H4** Thomas Moon Kang，[One Step From Eden 作者 itch 开发日志](https://thomasmoonkang.itch.io/osfe/devlog/50688/weekly-update-10-assassinate)。读取爆炸生成器/斩击序列与作者事后复盘。死亡事件触发爆炸链，并按敌人属性变化；作者也回顾某机制的重要性未达到原预期。没有据此复制其随机函数、帧数或声称玩家更爽。

## 范围、定义与来源脉络

这里的“像素”是最终画面/资产处理约束，不等于必须手绘、只能少色、不能缩放或必须某个帧率。已读作品本身提供三条路径：手工像素资产配程序变形（Celeste）、3D 模型转低分辨率序列（Dead Cells）、像素呈现配程序身体或材料模拟（Rain World / Noita）。需要先选项目目标，再决定在哪一层对齐像素网格；不能把一种管线的洁癖普遍化。

历史上早期主机的图块、精灵、色彩与显示数量约束塑造了表现方式；Shovel Knight 作者回顾这些限制时明确做了取舍。这只能说明一条影响脉络，不能据此断言“像素动画唯一始于某年/某作品”。动画阶段、姿态与残留运动还有传统动画脉络；本轮未完整读到 Lasseter 1987 原论文，故不把经典十二原则包装为已核验的像素游戏定律。

| 主题 | 本轮工作定义 | 主要职责与输出 |
| --- | --- | --- |
| 特效/动效 | 让行动、接触、材质变化、持续状态和结果在空间与时间上可辨认的表现系统。 | 事件表、形状/方向/阶段草图、颜色层级、遮挡预算、生成/停止策略、减效版本。若效果本身是模拟对象，还需系统规则。 |
| 人物动作 | 角色身体/武器如何表达正在做什么、如何施力、如何与环境接触。 | 动作词典、关键姿态或程序约束、锚点/碰撞说明、进入退出中断规则、测试转移序列。 |
| 物品动效 | 物体从出现到移动、待机、交互、使用/装备、消失的状态变化及反馈。 | 生命周期图、拾取/开箱/装备事件契约、实体轨迹和装饰偏移、库存结算对应、取消/重复/载入处理。角色伸手只算接口的一侧。 |

## 三项 Skill 的最强候选决策卡

以下每条“预期变化”都是要验证的预测，不是已经得到的玩家实验结果。数值、阈值由项目基线决定；不预先声称 4 帧、8 帧、12 fps 或固定停帧时长最优。卡片的执行流程是本文综合后的方案，来源不必逐条使用相同实现。

### F1：使特效的原因、范围和结束可追溯

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 玩家把挥空看作命中、效果仍亮却已无效、火焰看似装饰却会伤害，或效果重复触发。 |
| 候选解释 | 事件绑定错误；成功/失败共用过强反馈；视觉残留与有效持续期未区分；也可能是判定本身有错。 |
| 检查方法 | 同屏叠加输入接受、有效区域、结算事件和结束事件。用命中/挥空/被打断/离场各走一遍；对模拟材料记录状态转换。先确认逻辑，再评价视觉。 |
| 可执行修改 | 为效果写“谁、因何、在哪、持续到什么条件”；先画一个主形状表示方向/范围，再画确认与结束；把普通行动与成功结果用形状/位置/强弱区分。持续效果绑定状态寿命，结束后残留不得继续伪装成危险范围。 |
| 不适用情况 | 叙事幻觉或刻意误导可不即时揭示真实情况，但必须是已明确的体验目标；联网预测需定义确认/回滚，而非等服务器回复才有任何反馈。 |
| 预期变化 | 玩家更能回答“谁造成了什么、现在是否仍有效”；重复播放和无主效果减少。 |
| 验证与撤回 | 保留无特效/简化版对照；若误判来源没有下降，先撤新增装饰并重新检查判定；不能用加亮掩盖逻辑错误。 |
| 来源与状态 | Dead Cells、Celeste 代码作推导，H1/H4 提供独立一致性与边界；P1 是间接心理学证据。**跨案例一致的候选，未做目标项目实测**。 |

### F2：先标记信息功能，再减少视觉竞争

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 多单位/多效果同时出现时，看不清角色、威胁、落点或拾取物；减效后反而丢失机制信息。 |
| 候选解释 | 高亮/占屏面积/持续时间相互竞争；背景对比过强；粒子承担了未记录的提示或真实物理。 |
| 检查方法 | 把各层标记为实体模拟、危险边界、结果确认、气氛装饰；逐层关闭比较“还能否作同一个决策”，不能只比较截图是否干净。 |
| 可执行修改 | 为当前最重要事件保留一个清楚的主形状；收紧次要闪光、烟尘覆盖与残留；把必要边界和状态提示留在低特效版本。效果池上限只裁装饰实例，不能静默裁伤害实体或唯一预警。 |
| 不适用情况 | Noita 类材料模拟的像素、弹幕中的弹体不是可任意删掉的装饰；节奏游戏的时序信息也不能用普通战斗减效规则处理。 |
| 预期变化 | 同时发生多件事时，关键危险和下一步行动仍可辨认；低特效模式保留相同决策信息。 |
| 验证与撤回 | 比较同一录制/随机种子的普通与拥挤场景；逐项记录漏看对象。减效若造成新误判，恢复必要层，只撤次要强调。 |
| 来源与状态 | Shovel Knight 的清晰度取舍/全屏效果选项作推导，H1迫使规则收窄；P1不支持“越多越好”。**有反例修订的候选，尚无对本项目的可读性测量**。 |

### F3：一次性序列与持续模拟分别制作

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 爆炸只有不断膨大的圆、烟雾变成均匀噪点、魔法持续/消散难分，或补帧后冲击反而软。 |
| 候选解释 | 主轮廓和阶段未设计；生成器把所有实例均匀堆叠；管线不适合材料/玩法需求。 |
| 检查方法 | 序列效果只保留主轮廓检查起因、扩张/传播、主要作用、消散能否区分；模拟效果检查材料规则、边界、停止与残留。不要从静态拼图判断播放速度。 |
| 可执行修改 | 序列：先做少量阶段草图与实际播放，再补转折帧、碎片、光照；帧的停留时间由意图调整。模拟：先调传播/衰减/相互作用，再做渲染。记录预乘透明、像素采样、混合与相机缩放策略，验最终画面中的闪烁和轮廓。 |
| 不适用情况 | 不要求所有爆炸同一阶段数；持续火焰不必每次从“蓄力”起播；3D转像素不是手绘失败品。 |
| 预期变化 | 效果能以较少元素表达材质与阶段，修改时序/范围不需重做全部资产。 |
| 验证与撤回 | 以原尺寸、游戏速度、最坏背景播放；新增层若破坏轮廓则逐层退回；若模拟方式不支持必要交互，撤掉视觉假象并回到系统模型。 |
| 来源与状态 | Dead Cells 制作流程作推导；H1是模拟反例，H4支持序列+生成器混合；ArtStation R2只作管线实例。**限定范围的制作启发式，具体视觉质量待测**。 |

### A1：先选择动作表达方式，再精修

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 动作流畅但看不出方向/施力，攻击过软，或复杂地形上播放固定跑步导致明显滑行。 |
| 候选解释 | 关键姿态相似；功能阶段不清；补帧平均化；也可能需要程序接触而非更多序列帧。 |
| 检查方法 | 对姿态方案先遮住细节看轮廓和武器方向；对程序方案显示身体块、接触点、目标点；在平地、边缘、坡面/墙面分别检查。 |
| 可执行修改 | 固定动作先做准备/主要动作/回收等必要姿态并定时，再补帧；瞬时响应动作允许极短或没有可见准备。连续适应地形则先做身体约束、支撑与输入响应，再加肢体/尾巴表现。 |
| 不适用情况 | Rain World 类程序动画无需把每步都画成固定姿态序列；不能为了“有预备动作”擅自增加玩家输入延迟。 |
| 预期变化 | 动作意图和受力方向更明确；细化前即可发现状态/接触问题。 |
| 验证与撤回 | 同样输入播放粗稿和精修；精修降低辨识或响应就回退到关键阶段，不保留无作用的中间帧。 |
| 来源与状态 | Dead Cells、Celeste 推导；H3反驳普遍预制帧，已收窄。**跨管线反例检查后的启发式**。 |

### A2：用转移测试检查动画和控制权

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 跳跃仍播跑步、攻击被错误覆盖、受击结束仍锁输入、持物时手与物分离，或转场出现残留动作。 |
| 候选解释 | 状态优先级、过渡条件、中断清理或控制权归属不明确；片段本身可能没错。 |
| 检查方法 | 列“进入→保持→正常退出→被打断”的动作表；用移动→跳跃→拾取→受击→离场等短序列检查视觉、速度、控制权和绑定物同时是否一致。 |
| 可执行修改 | 为每个行为写可进入条件、可中断行为、退出清理；动画由真实速度/接触/能力状态选择或生成。短事件只触发一次，循环状态可持续；取消后清理拖尾、挂件、锁输入。 |
| 不适用情况 | 不强制某个引擎的 Animator 或统一有限状态机；过场可有不同控制权，但需声明恢复条件。 |
| 预期变化 | 更少卡动作、错误覆盖与中断残留；同一动作重入结果稳定。 |
| 验证与撤回 | 重复转移序列并记录差异；一项修改造成新的控制权问题时回退该转移，保留原动作素材。 |
| 来源与状态 | Celeste `UpdateSprite` 的状态分支与 Shovel Knight 修复记录支持检查；H3支持程序方案分支。**工程层跨案例一致，不是动画美感实验结论**。 |

### A3：分清绘制身体、碰撞身体和握持点

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 脚底漂移、缩放后埋地、翻面后武器换错手、夸张轮廓使玩家误判接触，或大角度旋转出现像素闪烁。 |
| 候选解释 | 各帧枢轴不一致；挂点坐标未随朝向处理；装饰身体被误用作碰撞；采样/变换与画面规则不一致。 |
| 检查方法 | 叠加脚底/握持点/碰撞体，逐帧与原速都看；检查左右转向、持物/空手、暂停、保存载入；记录哪个偏移是故意的表现。 |
| 可执行修改 | 规定共享枢轴和逐帧挂点；先稳定身体核心，再做服饰/头发/尾巴延迟；将视觉伸缩与碰撞变化分别声明，必要时调整玩家可见的接触提示。程序身体直接验证约束和接触，不强行固定轮廓。 |
| 不适用情况 | 碰撞体无需逐像素等于角色轮廓；风格化拉伸、程序肢体、3D转像素可保留，只需确保不误传重要接触信息。 |
| 预期变化 | 接触与握持连续，风格夸张仍保留稳定身份和可理解的碰撞。 |
| 验证与撤回 | 和原版同屏对照接触失败点；若新约束损害既定动作，撤约束而保留诊断叠层；不用静态截图宣称消除了动画闪烁。 |
| 来源与状态 | Celeste 缩放/持物代码、Dead Cells 管线取舍作推导；H3区分物理身体与装饰肢体。**依据有限的制作候选，需要实际逐帧和互动验收**。 |

### I1：将物品生命周期和结算写成契约

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 已经播拾取却没入包，入包后仍可重复拾取，开箱动画被跳过就丢奖励，或物体消失但理由不明。 |
| 候选解释 | 展示事件被误用作结算；重复触发；容量/权限拒绝没有反馈；转场或取消处理不完整。 |
| 检查方法 | 同时记录物品 ID、状态、拾取请求、接受/拒绝与库存变化；覆盖满包、多人同时请求、动画跳过、快速重按、死亡/转场/载入。单机没有的分支可以注明不适用。 |
| 可执行修改 | 最小生命周期写为“生成→掉落/就绪→请求→接受或拒绝→使用/持有→消失”；确定唯一结算权威并避免重复结算；表现监听结果，跳过或打断后仍恢复到真实物品与库存状态。 |
| 不适用情况 | 有意设计为实体飞到玩家身上才取得的玩法可以延后结算；需明示在途是否可丢失，不能假定接触瞬间就已拥有。 |
| 预期变化 | 玩家看到的取得结果与账面一致；重入/跳过不改变奖励数量。 |
| 验证与撤回 | 比较禁用动效和正常动效的结算日志；若逻辑结果不同，回退展示层对结算的依赖；不以“动画看起来对了”作为通过标准。 |
| 来源与状态 | Classic `fruit/chest`、Shovel Knight 拾取修复推导；H2补充掉落/宝箱问题。**工程候选有案例支撑；幂等方案为本文提案**。 |

### I2：让物品的等待、拒绝与成功有不同表现

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 悬浮误像正在拾取，上锁箱受击误像开箱，装备确认只闪一下却不知是否成功，悬停移开后一直发光。 |
| 候选解释 | 不同状态共用素材；循环/一次性误配； hover、focus 与确认事件混同；系统结果尚未明确。 |
| 检查方法 | 画物品状态表，对每条转换标注触发、能否取消、可交互性、结束姿态；实际比较“没资格”“接受”“已完成”能否区分。 |
| 可执行修改 | 待机用不妨碍辨识的循环；悬停/聚焦只表达可关注，不能表达已装备；拒绝回到原状态并说明原因；开箱停在真实开启状态；使用/装备以真实结果改变物体/槽位状态，随后再退掉强调。 |
| 不适用情况 | 不是所有物品都应持续浮动或发光；恐怖、伪装、探索目标允许隐藏可交互性。没有鼠标的游戏改测焦点/触控，不能强行加 hover。 |
| 预期变化 | 玩家能分辨等待、拒绝和完成，并知道下一步还能做什么。 |
| 验证与撤回 | 以任务问题检查状态判断；若新增循环干扰战斗，先改为静态就绪+事件反馈；若拒绝仍不清楚，检查文案/条件而非增加震动。 |
| 来源与状态 | Dig 作者资源目录只支持“可分离制作”的存在性；Classic 状态代码、Shovel Knight 与 H2故障记录支持逻辑边界。**美术语义部分待测，不标为跨作品视觉验证通过**。 |

### I3：为掉落/悬浮/抛掷明确谁真的在移动

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 物品在画面上够得到却捡不到，浮动碰撞导致时有时无，抛掷轨迹穿墙，或载入后位置/旋转跳变。 |
| 候选解释 | 装饰偏移与实体轨迹混用；碰撞区域没同步；物理状态没有持久化；真实运动被误当纯特效。 |
| 检查方法 | 同屏显示实体位置、绘制偏移、拾取区域、速度；检查静止、落地、弹起、被击飞、吸附、停止、载入，并核对相机移动。 |
| 可执行修改 | 选择并记录三种之一：纯装饰偏移、真实轨迹物品、可破坏/材料实体。装饰循环可改绘制偏移；真实抛掷/掉落要由物理或轨迹权威驱动；落地/拾取由接触条件触发而不是屏幕坐标动画完成。 |
| 不适用情况 | Noita 类物体移动/燃烧是玩法本体，不能固定碰撞体只让图飘；反之 UI 中的装备预览无需套世界物理。 |
| 预期变化 | 视觉可达性与交互可达性更一致，保存载入不改变物品语义。 |
| 验证与撤回 | 相同初始条件对照不同帧率/暂停/载入；若变更影响原有玩法轨迹，退回物理参数，仅修绘制偏移和提示；记录允许的不确定性。 |
| 来源与状态 | Classic 悬浮与 Celeste `Throw/Drop` 作推导；H1/H2提供强边界反例。**跨案例一致的分类规则，具体动画参数待测**。 |

### 两篇原始论文

- **P1** Kao, Ballou, Gerling, Breitsohl, Deterding（CHI 2024），[How does Juicy Game Feedback Motivate?](https://publikationen.bibliothek.kit.edu/1000171104/152952099)，[DOI](https://doi.org/10.1145/3613904.3642656)。读取摘要、设计含义和局限章节；预注册在线实验 n=1,699，使用专门的动作 RPG。成功依赖反馈与动机的关系为候选规则提供间接支持；该实验的放大条件反而降低部分体验指标。作者将能动性/因果绑定受阻列为可能解释，不是已经单独验证的机制。不能推出像素动画固定参数，也不能推出全部游戏增加特效都不好。
- **P2** Martin Pichlmair、Mads Johansen（2020预印本/后续期刊），[Designing Game Feel: A Survey](https://arxiv.org/html/2011.09201v1)，[期刊 DOI](https://doi.org/10.1109/TG.2021.3072241)。读取摘要、III/IV相关分类与未来工作；是综述，不是新玩家对照实验。它把物理性、强调与支持区分开，为避免将动画、判定、反馈混为一谈提供术语；不能据综述称本报告的9条规则得到实验验证。

## 给实施 Skill 的交付要求

先让 AI 读取项目已有资产和事件，不直接发起完整重做。最小输入：目标动作/物品、要表达的状态、视角/最终显示尺寸、渲染管线、玩法/结算权威、控制设备、已有示例、可调参数。缺失项写成假设，不凭“像素游戏”擅自填写。

三类输出分别是：

1. **特效规格**：事件→主形状/方向→必要信息层→开始/持续/结束→减效替代→验证场景。
2. **人物动作规格**：行为→姿态序列或程序约束→挂点/碰撞→控制权→中断/重入→逐帧与原速验收。
3. **物品动效规格**：生命周期→真实结算→显示/物理分层→开关/拾取/掉落/装备/使用/悬停→取消与恢复→日志对照。

复核时至少保留：原版、最小修改版、拥挤/低特效版，以及能重现输入或事件的记录。先检查“实际状态是否对”，再检查“玩家是否读对”，最后评估“是否符合目标风格”。只有目标项目的操作/观察支持预期且未损害玩法，规则才可由“案例支持候选”升为“本项目实测”；不能用本报告替代这一步。
