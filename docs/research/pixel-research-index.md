## 各技能得到了什么

| Skill | 有限支持或收窄后的结论 | 尚不能由本次材料确认 |
|---|---|---|
| pixel-character-art | 在实际场景分配身份识别线索 C1 | 连续状态的身份保持 C2、完整方向和镜像 C3 |
| pixel-environment-art | 边界按玩法语义分级 S1、模块与必要地标 S2 | 引擎遮挡、碰撞与导航效果 S3 |
| pixel-item-art | 识别粒度 I1、世界／提示版本 I2、必要交互线索 I3 | 实际误选率、完整交互身份和获得行为 |
| pixel-ui-layout | 按当前决策分区 L1 | 跨设备方法 L2 只有一个直接案例；分层比例 L3 为反例驱动工程提案 |
| pixel-icon-button-art | 图标与可查名称配合 I1 | 全状态识别 I2、真实命中区 I3 |
| pixel-ui-interaction | 对已知决策信息的预览 X2 | 焦点恢复 X1、多输入可达性 X3；撤销边界由玩法决定 |
| pixel-vfx-motion | 原因与状态对应 F1；功能分层 F2、序列／模拟分流 F3 经反例收窄 | 减效后的实际可读性、精确时长和像素轮廓表现 |
| pixel-character-animation | 预制／程序方案分流 A1、控制与转移关系 A2 | 接触与挂点的实际连续性 A3、动画美感和响应效果 |
| pixel-item-animation | 生命周期检查 I1、显示偏移／真实运动分类 I3 有案例依据 | 幂等架构为本项目提案；状态视觉语义 I2、项目结算正确性仍需运行 |

工程建议可以很有用，但不因此升级为跨作品玩家实验结论。各技能保留其最弱证据环节，不用“行业常识”抹去缺口。

## 来源覆盖

已读取作者教程、游戏开发日志、公开源码、论文和官方工具／无障碍说明；已实际查看静态美术与 UI 研究所列的官方截图/图示。Steam、itch 提供作者发布的资料与案例入口；少量记录的市场指标只用于说明取样背景。

ArtStation 来源有作者归属，但部分仅能阅读文字。YouTube／Bilibili 大多只读到页面、索引、出处或演讲幻灯片，尚未完成视频内容和高赞高收藏指标核验。Pinterest 未建立足够可靠的原作链。这几项是明确保留的研究缺口；本版不宣传为完成全部平台的视频蒸馏。

原书、论文全文、游戏原图和视频没有进入仓库。完整报告注明访问范围与链接，Skill 内含可独立携带的相关证据摘要。

## 后续怎样升级规则

先补与具体预测匹配的证据：状态问题要连续状态，焦点问题要输入轨迹，碰撞问题要引擎数据，动画时序要实际播放。再按相同条件检查原版和最小修改，记录反例及副作用。只有该项目的实际观察支持预测，才标为“本项目实测”。
