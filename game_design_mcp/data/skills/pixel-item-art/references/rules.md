# 像素物品美术：条件规则卡

研究日期：2026-11-09。预期变化是待检查的预测；来源与状态限定每条规则的使用范围。执行方案由本项目综合提出，不代表所有参考作品使用了同一实现。

依据见 [来源与案例](evidence.md)。先读触发条件与例外，再采用最小可撤回修改。

## I1 先建立物品的区分层级，再分配形状细节

- **触发条件：**物品表好看，但在世界或背包中把不同用途物品认错。
- **候选解释：**区别只在小色差；形状被缩小丢失；项目要求识别的粒度超过图像预算。
- **检查方法：**列任务需要区分的粗类别和精确品种；分别看实际尺寸、轮廓和完整图，再检查名称/数量是否本来就会辅助识别。
- **可执行修改：**用途类别→轮廓与结构差异→实际场景和物品格并排→在最相近类别间补一条非颜色线索→最后加材料纹理。不要让每种作物都被迫拥有完全不同剪影。
- **不适用情况：**蓄意难辨的鉴定/伪装玩法；同一功能的颜色变体可以相近，前提是任务允许。
- **预期变化：**需要快速区分的类别更明确，精细差别由合适的图像或文字承担。
- **验证与撤回：**使用项目的真实混淆对进行命名/选择任务；若改造破坏类别共性或世界设定，撤回过度变化，增加标签或详情。
- **来源与状态：**S06 工艺；S08/S09 推导；S12 多人农场收窄识别粒度。`narrowed`，没有实际误选率。

## I2 依据使用场景统一语法，允许世界图与提示图不同

- **触发条件：**单独展示漂亮，放进地图后比例奇怪、视角突兀或接地不清。
- **候选解释：**直接复用库存图作世界物；投影、像素密度或锚点不匹配；用途需要的可见大小与现实比例冲突。
- **检查方法：**把物品与角色、地格、邻近物、提示栏同时摆出，写明各版本在做什么；不要只比较统一画布尺寸。
- **可执行修改：**先做世界展示稿→按投影和接地点调整→在明暗场景检查→另做需要的库存/获取提示版本→共享身份线索，分别记录尺寸与用途。
- **不适用情况：**信息提示可有自己的视角或夸张尺度；世界内被举起/展示的物件也可服务可见性。不强制物理比例一比一。
- **预期变化：**同一物品跨场景仍可对应，进入地图时更协调。
- **验证与撤回：**对照世界物、手持图、提示图做身份配对；若语法一致却难读，允许有记录的展示例外，不死守尺寸。
- **来源与状态：**S05/S06 工艺；S08/S09 世界画面；S12 举起蔬菜和提示给出有用边界。`case-supported`。

## I3 仅对需要被发现的交互对象建立一致线索

- **触发条件：**关键物品被当装饰，或场景所有物件都加发光后目标更难找。
- **候选解释：**交互类别没有视觉约定；线索竞争；也可能玩家不懂操作或目标。
- **检查方法：**标出必须发现、可选探索、纯装饰三类；检查当前任务与提示，不能把所有不发光物件都判为失败。
- **可执行修改：**先定义一类交互对象的共同形状/位置/边缘线索→与装饰混排→只修实质歧义→必要时将靠近提示交给交互系统。不要靠稀有度强光替代对象本身的类别设计。
- **不适用情况：**隐藏物、推理线索、成熟且已被玩家学习的环境约定；需避免提前泄露谜底。
- **预期变化：**关键对象更容易被识别为当前可行动目标，同时保留环境层次。
- **验证与撤回：**观察指定任务中的漏找/误找与提示触发；若强化线索抢占危险信息或泄密，撤回强化，改用更局部的交互反馈。
- **来源与状态：**S08/S09 浮空对象推导；S12 农作物/箱子缺少统一发光是对强标记假设的边界。`narrowed`，不声称已检查游戏全部交互对象。
