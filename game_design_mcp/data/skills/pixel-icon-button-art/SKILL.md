# 像素图标与小按钮美术

使图标表达可辨认的含义，使按钮外观表达可操作性和当前状态。

## 进入任务

优先读取用户已有项目与素材。核对：语义和动作；已有图标家族；最小实际显示尺寸；输入方式；背景；按钮状态；是否允许文字提示；本地化要求。

已明确的选择直接沿用。缺少非阻塞信息时写出暂定条件；只有会改变制作结果的分歧才提问。区分原始素材尺寸、屏幕显示尺寸与引擎坐标，不默认 16×16、固定色数或固定帧数。

## 执行

根据当前问题阅读 [规则卡](references/rules.md)，需要依据或检验边界时阅读 [来源与案例](references/evidence.md)。先确认触发条件，再选择修改；案例支持不代表当前项目已经验证。

1. 写清每个符号指代对象还是执行动作；先查项目已有语言，再做候选隐喻。不能仅凭作者认识就认定新用户会懂。
2. 在最小实际尺寸比较轮廓、内部留白和关键部件，优先修复同组混淆；放大像素检查只帮助修改。
3. 区分图形可见边界、控件布局边界和点击/触控区域；保持图标美术尺寸的同时，可以让输入区域更大。检查相邻区域冲突。
4. 为适用的默认、悬停、焦点、按下、选中、禁用提供可区分状态，按输入方式裁剪；选中与焦点不同步时应能同时表达。
5. 交付同组图标板、状态板、命名与语义表、导出尺寸和输入区域标注。未检验的隐喻保留标签或说明方案。

## 交付与验收

按任务交付实际资产、实现或可制作规格；没有相应工具时明确交付层级。规格应包含：图标/按钮 ID、语义、动作、原始像素尺寸、显示变换、图形边界、输入边界、状态层、标签/提示、导出命名。

重点检查：最小显示与复杂背景；近似符号成对比较；键盘焦点与选择并存；禁用可读性；实际点击区域及间距。

报告采用的规则 ID、比较条件、观察结果与未测项。保留修改前版本；未改善目标问题或损害另一关键任务时，回退该改动并检查其他解释。用户只要求局部修改时，围绕该问题给出所需内容。
