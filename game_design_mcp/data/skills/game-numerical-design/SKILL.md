# 游戏数值设计与拆解

先把任务写成一个玩家能观察到的变化，例如「买第一把剑后，打同一只怪少挥一刀」。给出对照场景、初始状态、计时起点、目标范围和必须保持的约束。有配置就沿用项目单位和结算顺序，缺少数据时标出试算假设。

## 拆参考游戏

沿「准备 → 属性与成长 → 战斗公式 → 经济循环与付费 → 整合分析」取证。只做任务相关的部分。涉及讲师的观点、术语或出处时，读取[四课观点与出处](references/课程观点.md)。

- **准备。** 固定版本、攻守双方、技能和场景。每行记录输入、结果和变动项。随机伤害另记样本量和波动区间，区分普通命中与暴击。
- **属性与成长。** 画出「加点或消耗 → 面板属性 → 战斗结果」。比较相邻等级的绝对增量和倍率，再看突破、解锁等断点。说明本项目中「一级、二级」的具体含义。
- **战斗公式。** 对同一目标只改攻击，比较减法、比例减伤或分段等候选。再改变防御，区分仍能解释原数据的公式。取一组未参与反推的条件做预测，留下预测值、观测值和误差。取整、最低伤害、技能倍率、暴击或护盾可能掩盖差异。少量观测只支持候选公式。
- **经济循环。** 按同一时间窗列资源从哪来、花在哪、换来什么、多久够用。若存在付费，分别计算免费与付费路径的等待、成长上限或胜算。
- **整合。** 用一条因果链说清哪类玩家在哪个阶段获得了什么、付出什么、有没有新的选择。保留一个反例或下一次最能区分解释的测量。

## 设计或调整自己的游戏

从结果往回算。选一个有代表性的等级、敌人或资源目标，写出目标节奏，再填配置。

| 玩家问题 | 计算方法 | 交付前复核 |
|---|---|---|
| 成长何时有感 | 从目标击杀次数、行动窗口或解锁条件反推核心属性，给升级前后都算一次 | 面板增益是否跨过玩家能感到的门槛？ |
| 战斗有多少余量 | 对比玩家击倒敌人和敌人击倒玩家的时间。定伤命中用向上取整的击数，再按首击时点、攻击间隔、恢复和无敌阶段换算实际时间 | 区分理论站桩与实际操作。随机伤害检查失败尾部 |
| 同期任务奖励怎么定 | 在相似条件下选可重复活动作价值基准，将金币、经验和道具折成同一单位。强度或阶段变化时重估单位时间产出 | 查明奖励是否可兑换及当前用途，分别说明等价总量与玩家偏好 |
| 资源总是缺或总是满 | 选个人或全体玩家的账本。期末库存等于期初加流入减流出。区分交易转移、系统回收和资源转成长 | 用目标缺口除以可用净收入，并处理每日上限、整数结算和首笔到账。净收入非正、库存又不足时，持续积攒无法达标 |

将局部改动代回完整循环。提高伤害可能增加每分钟击杀数、加快掉落并缩短下次升级等待。一次优先改能区分原因的一个量，给出旧值、新值、单位、预期行为、验证和撤回条件。可参考[演算示例](references/演算示例.md)。

交付一张可复算的前后对照表，注明哪些结果来自实测、哪些来自配置计算、哪些仍需试玩。


## v0.1.0 MCP 配套

连接 game-design-skills-mcp 后，先用 `list_capabilities` 发现接口，再使用 `calculate_combat`。参数以工具 JSON Schema 为准。服务不写文件，返回的代码由调用方在授权项目中接入。结构检查不能证明实际乐趣；通用特效不代表原游戏复刻。未连接服务时按本文执行，不伪造工具结果。
