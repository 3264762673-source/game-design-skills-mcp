# 游戏手感与体验设计

把“更爽”变成玩家能够感知、理解并归因于自身行动的变化。此 Skill 是基于公开试读、作者文章与论文形成的操作工具；不是几本书的全文替代品。出处和阅读范围见 [sources.md](references/sources.md)。

## 先确定要改变的体验

从用户提供的项目、录像、代码或描述中确定：核心动作、输入设备、目标平台、目标玩家、当前症状，以及允许修改的范围。缺少信息时先做可观察的诊断；不能运行或看不到画面时，交付假设与实现规格，不声称已试玩。

把目标写成一句话，例如：“重击命中时，玩家能指出接触对象，感到力量集中，并看清下一次攻击。”分别记录：

- 感官目标：清脆、沉重、柔软、流畅等，选与项目有关的词。
- 行为目标：识别命中、控制落点、解释成功原因、选择下一步。
- 情绪目标：掌握、惊喜、释放、安心、表达等；不默认所有游戏都追求高刺激。
- 约束：玩法数值、联机判定、视觉风格、帧预算、减效设置中哪些必须保持。

## 诊断并选择决策卡

先分清输入未接受、状态未改变、结果不可见、结果无意义。优先解决证据支持的上游问题；帧耗时或判定错误转入项目的调试流程，修复后重新评价手感。

| 症状 | 阅读与选择 |
|---|---|
| 不跟手、连按、感觉击中却没有结果 | [interaction-vfx.md](references/interaction-vfx.md)：F01、F02 |
| 所有技能像同一种光团、力量与材质不明确 | [interaction-vfx.md](references/interaction-vfx.md)：F03 |
| 范围误判、满屏特效、低画质丢失信息 | [interaction-vfx.md](references/interaction-vfx.md)：F04、F05 |
| 持续轰炸却没有高潮，胜利与成长无感 | [experience.md](references/experience.md)：E01、E02 |
| 选择无意义、奖励驱动重复却不满意 | [experience.md](references/experience.md)：E03、E04 |
| 创造或探索玩法缺少个人表达空间 | [experience.md](references/experience.md)：E05 |

每轮优先处理最关键的一个问题，必要时带一个直接相关问题。给选中卡填入项目证据；没有证据的候选解释保持“待测”。不把所有卡一口气套用。

## 变成可执行修改

按 [experiment-template.md](references/experiment-template.md) 记录基线、单项假设、事件时序、修改位置、验证和回退。具体毫秒数、曲线、亮度、音量、并发上限由当前项目和设备确定，标为初始试调值；不编造通用“爽感参数”。

实现时保持这些关系：

- 输入确认、动作开始、命中判定、造成伤害、击杀分别命名。表现读取对应事件；挥空可以有挥动特效，但不能播放已命中的确认。预测反馈必须与确认反馈可区分，并遵循已有校正机制。
- 把主轮廓、关键接触或范围信息先做清楚，再添加装饰。特效生命周期包含生成、更新、取消、结束和资源回收；暂停、重开、对象销毁后不留残影或声音。
- 镜头、全局停帧、混音压低由项目既有统一入口管理。仅为增强表现时，不暗改伤害、碰撞、冷却或权威模拟时间。
- 高密度、静音和减效条件仍能传达必要结果与威胁。根据实际症状削减装饰；不要靠更亮、更响、更强震动覆盖问题。

本环境若已有 `kunlun-screen-feedback`、`kunlun-combat-quality-orchestration` 或对应武器技能，进入具体战斗实现时读取适用技能并复用事件契约；它们是可选实现配套，不是本 Skill 的安装依赖。其他项目沿用自己的架构。

## 用试玩决定保留什么

比较原版与修改版；只改一个可解释因素，或明确声明测试的是整组方案。使用相同场景和设备，交替版本顺序。重复命中可用固定输入回放，体验评价仍需真人实际操作。

同时记录行为证据、玩家主观感受和代价。目标改善但误判、遮挡、不适或性能超出项目容忍范围时，调整或回退。小样本发现用于下一轮决策，不声称普遍有效；未测记“待测”，结果冲突记“暂不确定”。

不要把停留时长、点击次数或再次尝试单独当成愉悦证据。不要将多巴胺、心流、潜意识包装成保证生效的特效公式。精神分析卡只用于自愿表达玩法的设计假设，不解释玩家人格，也不宣称治疗作用。

## 完成时交付

1. 症状、证据、目标和采用的决策卡。
2. 已完成的改动，或足够实施的事件与参数规格；清楚区分两者。
3. 比较条件、结果、未验证项，以及保留／继续试调／回退的结论。
4. 来源 ID、证据类型、项目测试状态。引用来源时按 [sources.md](references/sources.md) 的真实阅读范围表述。

用户只要求设计时，规格与验证计划即可完成；用户要求改项目时，在授权范围内完成实现及可执行的验证。


## v0.1.0 MCP 配套

连接 game-design-skills-mcp 后，先用 `list_capabilities` 发现接口，再使用 `create_effect_bundle / validate_decision_card`。参数以工具 JSON Schema 为准。服务不写文件，返回的代码由调用方在授权项目中接入。结构检查不能证明实际乐趣；通用特效不代表原游戏复刻。未连接服务时按本文执行，不伪造工具结果。
