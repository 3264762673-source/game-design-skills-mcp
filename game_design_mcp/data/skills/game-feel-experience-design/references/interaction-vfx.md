# 操控、交互与特效决策卡

来源 ID 见 [sources.md](sources.md)。以下检查程序、参数隔离和回退方案是本 Skill 的工程化设计，不是原书逐条指令。初始状态均为“来源支持部分原理；本项目待测”。

## F01：输入有了，控制感没有建立

- **触发条件**：玩家反复按键、频繁反向修正，或描述动作迟钝、漂移。
- **候选解释**：输入未采到、被状态拒绝、反应延迟；也可能是加减速曲线与空间尺寸不匹配，而非反馈太少。
- **检查方法**：对齐输入采样、接受／拒绝、状态切换、第一帧可见响应的记录。分别测试起步、停止、转向和目标落点；在相同设备、固定帧率条件下观察。只有录像时不要把显示延迟归因到某段代码。
- **可执行修改**：先修正已证明的漏输入或错误状态；若逻辑正确，再一次调整一个响应参数或一个场景尺度。冷却／锁定拒绝输入时给出简洁状态依据。输入缓冲、宽限时间会改变操作规则，只有范围允许时才试，且限定适用状态与失效时刻。
- **不适用情况**：刻意的惯性已经可预测且是玩法核心；联机延迟或帧率故障尚未排除。此时不直接消除惯性或增加粒子。
- **预期变化**：多余重复输入和落点修正减少，玩家更能预测停止或转向位置。
- **验证与撤回**：原版／修改版各做同组动作，记录失误及控制感评价。改后出现意外动作、技能表达减少或越界，则恢复参数，保留诊断记录。
- **来源与状态**：S01 的输入—响应—空间关系为设计经验；时间戳链与隔离测试为工程推导，待项目验证。

## F02：反馈要能回答“我对谁做成了什么”

- **触发条件**：玩家看见华丽闪光，却不确定是否命中、破盾、击杀，或因反馈误以为成功。
- **候选解释**：反馈绑在按键而非结果；对象不明确；动画、声音与判定不同步；多次订阅造成重复播放。
- **检查方法**：逐帧对照事件 ID、目标 ID 和实际状态；分别回放挥空、普通命中、护盾吸收、击杀。检查一个事件是否被重复消费。
- **可执行修改**：保持挥动与接触两套语义；在实际受影响对象上显示与结果对应的短反馈。以判定事件对齐接触动画、声音和局部 VFX；无伤害的格挡不复用造成伤害的确认。异步结算则分开表现“已发出”和“已确认”。
- **不适用情况**：玩家已能准确描述结果，问题出在后续目标、决策或收益，转 E02／E03。
- **预期变化**：命中类型识别和目标归因更准确，无效补按减少。
- **验证与撤回**：在不展示日志时让试玩者复述结果，再与日志核对。若识别不升反降，移除新增通道；若出现虚假命中，先修正事件绑定再测试。
- **来源与状态**：S02 的可感知事件与情绪关联、P03 的成功依赖反馈提供依据；事件去重与目标绑定为工程推导，待测。

## F03：先制作运动和力量，再补纹理

- **触发条件**：重击、火焰、流水或魔法只有颜色不同；爆炸像匀速放大的光圈，缺少材料和力量方向。
- **候选解释**：主要形状与运动曲线相同；起势、扩张和消散没有区别；细节掩盖主要动作。
- **检查方法**：关闭装饰层，以单色轮廓查看完整运动。标出能量来源、主要传播方向、接触点和衰减路径；请观察者用自己的词描述材质与力量，不预告期望答案。
- **可执行修改**：制作少量关键姿态／轮廓，先确定主要位移和体积变化，再试速度曲线，最后加碎屑、烟与光。爆发可试快速扩张后衰减；火与烟可试向上翻卷而非贴图整体拉伸。根据真实或艺术参考选定运动特征，给次级元素不同但相关的寿命与方向。攻击若可被打断，取消时收束未发生的后续效果。
- **不适用情况**：抽象符号风格本身不模拟物理；不要强迫其写实。这里的分层制作也不能代替引擎材质、粒子系统的具体教程。
- **预期变化**：仅凭运动即可区分力量方向和效果身份；装饰减少后关键感受仍保留。
- **验证与撤回**：比较轮廓版与装饰版，再放回实际游戏距离及背景。若新曲线造成范围误判，转 F04 修正；若只有静态截图更漂亮，保留更清晰的动态方案。
- **来源与状态**：S03 仅提供已读试读中的爆炸扩张、火焰运动线索；S04 提供形状／时间／风格评价维度。分层制作流程为工程推导，并非已读全书教程，待测。

## F04：可见边界和生效时刻要可信

- **触发条件**：玩家离开光圈仍受伤，或特效结束后仍认为技能有效；不同画质影响避险判断。
- **候选解释**：装饰范围与判定混淆；预警、有效、消散阶段共享同一种外观；透视或背景让边缘不可辨。
- **检查方法**：叠加调试碰撞范围与时间轴，检查视角、屏幕边缘、浅深背景和各画质。区分边界不准、视觉不可见和网络校正，不能一律归为玩家反应慢。
- **可执行修改**：给有效区域稳定的辨识依据；将无伤害烟尘、残光从有效范围标识中分离。用至少一个稳定的形状或动态区别提示阶段，而非只换颜色。低画质优先削减装饰，保留相同玩法信息。
- **不适用情况**：有意隐藏的信息是用户明确的玩法要求；应检验该玩法是否可学习，不擅自显示全部判定。
- **预期变化**：范围和阶段识别改善，因表现误导导致的受击减少。
- **验证与撤回**：让玩家标出安全区域／生效时刻，与权威状态比较。改后误差增加则回退；性能不足时降低装饰成本，不删掉关键边界。
- **来源与状态**：S05 为具体竞技游戏的制作案例；迁移到其他品类的边界与阶段方案为工程假设，待测。

## F05：并发越多，越需要挑选重点

- **触发条件**：单次特效好看，群战却看不清威胁、听不见关键音、出现疲劳或掉帧。
- **候选解释**：同一反馈被高频重复；所有事件使用同等亮度、音量或镜头强度；装饰持续时间超过事件间隔。
- **检查方法**：在目标设备高密度场景记录事件频率、同时存活效果、帧耗时和漏看威胁。依次关闭镜头、装饰粒子、叠加音，定位造成问题的层。
- **可执行修改**：给危及当前行动的信息优先级；高频同类装饰允许合并或限频，关键状态变化保持可识别。收短非必要尾迹；镜头和声音通过统一入口设并发与恢复策略。静音／减效时用较稳定的局部信号保留必要信息。
- **不适用情况**：只有低频单次场景，或拥挤来自敌人行为本身；不将所有效果统一调弱，也不靠删反馈修数值压力。
- **预期变化**：高密度场景的威胁识别改善，峰值时刻仍可突出，性能和舒适度符合项目目标。
- **验证与撤回**：相同密度对比普通与减效模式，记录漏看、主观不适和帧耗时。若合并吞掉关键事件或让技能身份消失，恢复这些事件的独立表达。
- **来源与状态**：S04、S05 支持清晰度与预算取舍；P03 不支持一味增强。并发仲裁与消融流程为工程推导，待测。
