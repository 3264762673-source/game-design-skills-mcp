# 像素人物动作：条件规则卡

研究日期：2026-11-09。预期变化是待检查的预测；来源与状态限定每条规则的使用范围。执行方案由本项目综合提出，不代表所有参考作品使用了同一实现。

依据见 [来源与案例](evidence.md)。先读触发条件与例外，再采用最小可撤回修改。

## A1：先选择动作表达方式，再精修

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 动作流畅但看不出方向/施力，攻击过软，或复杂地形上播放固定跑步导致明显滑行。 |
| 候选解释 | 关键姿态相似；功能阶段不清；补帧平均化；也可能需要程序接触而非更多序列帧。 |
| 检查方法 | 对姿态方案先遮住细节看轮廓和武器方向；对程序方案显示身体块、接触点、目标点；在平地、边缘、坡面/墙面分别检查。 |
| 可执行修改 | 固定动作先做准备/主要动作/回收等必要姿态并定时，再补帧；瞬时响应动作允许极短或没有可见准备。连续适应地形则先做身体约束、支撑与输入响应，再加肢体/尾巴表现。 |
| 不适用情况 | Rain World 类程序动画无需把每步都画成固定姿态序列；不能为了“有预备动作”擅自增加玩家输入延迟。 |
| 预期变化 | 动作意图和受力方向更明确；细化前即可发现状态/接触问题。 |
| 验证与撤回 | 同样输入播放粗稿和精修；精修降低辨识或响应就回退到关键阶段，不保留无作用的中间帧。 |
| 来源与状态 | Dead Cells、Celeste 推导；H3反驳普遍预制帧，已收窄。**跨管线反例检查后的启发式**。 |

## A2：用转移测试检查动画和控制权

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 跳跃仍播跑步、攻击被错误覆盖、受击结束仍锁输入、持物时手与物分离，或转场出现残留动作。 |
| 候选解释 | 状态优先级、过渡条件、中断清理或控制权归属不明确；片段本身可能没错。 |
| 检查方法 | 列“进入→保持→正常退出→被打断”的动作表；用移动→跳跃→拾取→受击→离场等短序列检查视觉、速度、控制权和绑定物同时是否一致。 |
| 可执行修改 | 为每个行为写可进入条件、可中断行为、退出清理；动画由真实速度/接触/能力状态选择或生成。短事件只触发一次，循环状态可持续；取消后清理拖尾、挂件、锁输入。 |
| 不适用情况 | 不强制某个引擎的 Animator 或统一有限状态机；过场可有不同控制权，但需声明恢复条件。 |
| 预期变化 | 更少卡动作、错误覆盖与中断残留；同一动作重入结果稳定。 |
| 验证与撤回 | 重复转移序列并记录差异；一项修改造成新的控制权问题时回退该转移，保留原动作素材。 |
| 来源与状态 | Celeste `UpdateSprite` 的状态分支与 Shovel Knight 修复记录支持检查；H3支持程序方案分支。**工程层跨案例一致，不是动画美感实验结论**。 |

## A3：分清绘制身体、碰撞身体和握持点

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 脚底漂移、缩放后埋地、翻面后武器换错手、夸张轮廓使玩家误判接触，或大角度旋转出现像素闪烁。 |
| 候选解释 | 各帧枢轴不一致；挂点坐标未随朝向处理；装饰身体被误用作碰撞；采样/变换与画面规则不一致。 |
| 检查方法 | 叠加脚底/握持点/碰撞体，逐帧与原速都看；检查左右转向、持物/空手、暂停、保存载入；记录哪个偏移是故意的表现。 |
| 可执行修改 | 规定共享枢轴和逐帧挂点；先稳定身体核心，再做服饰/头发/尾巴延迟；将视觉伸缩与碰撞变化分别声明，必要时调整玩家可见的接触提示。程序身体直接验证约束和接触，不强行固定轮廓。 |
| 不适用情况 | 碰撞体无需逐像素等于角色轮廓；风格化拉伸、程序肢体、3D转像素可保留，只需确保不误传重要接触信息。 |
| 预期变化 | 接触与握持连续，风格夸张仍保留稳定身份和可理解的碰撞。 |
| 验证与撤回 | 和原版同屏对照接触失败点；若新约束损害既定动作，撤约束而保留诊断叠层；不用静态截图宣称消除了动画闪烁。 |
| 来源与状态 | Celeste 缩放/持物代码、Dead Cells 管线取舍作推导；H3区分物理身体与装饰肢体。**依据有限的制作候选，需要实际逐帧和互动验收**。 |
