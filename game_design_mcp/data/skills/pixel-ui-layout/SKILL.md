# 像素 UI 布局

依据当前玩家任务分配屏幕空间，使世界、读数、控件和说明在目标设备上可用。

## 进入任务

优先读取用户已有项目与素材。核对：页面任务；优先信息；平台/屏幕/输入方式；世界画面需求；字体与语言；缩放、长文本和安全区；现有组件。

已明确的选择直接沿用。缺少非阻塞信息时写出暂定条件；只有会改变制作结果的分歧才提问。区分原始素材尺寸、屏幕显示尺寸与引擎坐标，不默认 16×16、固定色数或固定帧数。

## 执行

根据当前问题阅读 [规则卡](references/rules.md)，需要依据或检验边界时阅读 [来源与案例](references/evidence.md)。先确认触发条件，再选择修改；案例支持不代表当前项目已经验证。

1. 先确定当前决策需要同时看到的对象：动作目标、资源、后果或比较项；画信息分组与区域分配，不先画装饰框。
2. 分别定义世界渲染、UI、字体和输入区域的尺度；如果选择统一网格，也要验证长文本和触控，不把统一网格当作像素风的资格条件。
3. 用真实长短内容填充布局，明确溢出、滚动、分页和弹层策略；文字与数字按阅读任务对齐。
4. 把焦点态、选中态、说明面板和错误反馈放进版面，检查它们是否遮挡当下要比较的内容；输入图关系留给交互规格。
5. 交付布局样板、尺寸约束和缩放矩阵，展示最窄屏幕、长文本与最高信息密度条件；只将已实测尺寸写为通过。

## 交付与验收

按任务交付实际资产、实现或可制作规格；没有相应工具时明确交付层级。规格应包含：页面 ID、任务优先级、区域约束、尺度单位、字体策略、间距与对齐、溢出行为、弹层、焦点可视区、适配样例。

重点检查：目标窗口/显示比例；最长本地化文本；战斗高密度画面；键盘/手柄焦点；触控遮挡；文字与游戏画面独立缩放。

报告采用的规则 ID、比较条件、观察结果与未测项。保留修改前版本；未改善目标问题或损害另一关键任务时，回退该改动并检查其他解释。用户只要求局部修改时，围绕该问题给出所需内容。
