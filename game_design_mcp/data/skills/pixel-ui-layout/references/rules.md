# 像素 UI 布局：条件规则卡

研究日期：2026-11-09。预期变化是待检查的预测；来源与状态限定每条规则的使用范围。执行方案由本项目综合提出，不代表所有参考作品使用了同一实现。

依据见 [来源与案例](evidence.md)。先读触发条件与例外，再采用最小可撤回修改。

## L1 — 先确定当前决策所需内容，再分配区域

1. **触发条件**：玩家为一次决定在多个角落来回找目标、成本、后果；或者菜单占用了需要观察的游戏区域。
2. **候选解释**：信息分组错误、当前对象没有明确标识、无关内容抢占空间；也可能是规则没讲清而非布局问题。
3. **检查方法**：写出一个具体任务，例如“选物品并判断对本回合的帮助”；将所需信息标成当前对象、长期状态、条件详情三类；在真实分辨率截图标出每次查找点。先检查数据是否真的存在。
4. **可执行修改**：固定长期状态的相对位置；把当前对象及其详情建立清楚对应；按任务切换主要工作区。对比操作所需的信息尽量同屏或保留可恢复的参照，而不是机械追求最少元素。
5. **不适用情况**：隐藏信息本身就是谜题；桌面整理、空间记忆是玩法。不能以“整洁”为由消除玩法约束。
6. **预期变化**：减少找错对象、漏看成本和无目的跨区扫视；只是设计预期，未实测。
7. **验证与撤回**：用原版/修改版执行同一组正常、满背包、长文本任务；记录漏项、操作完成、遮挡。若查找改善却使比较信息不可得，恢复旧分区并改为按需详情。不要只问“更好看吗”。
8. **来源与状态**：[S02](https://media.gdcvault.com/gdc2019/presentations/Into%20the%20Breach%20Postmortem%20Final.pdf)、[S03](https://papersplea.se/)、[S10](https://store.steampowered.com/app/1970580/Backpack_Hero/) 的观察启发；执行步骤为本次推导。跨作品案例支持，无因果证明。

## L2 — 屏幕改变时重排任务，保留不可丢失的比较关系

1. **触发条件**：把桌面 UI 缩到手机/掌机后，文字、点击或并列比较无法完成。
2. **候选解释**：不只是字体小，可能是横屏任务空间与竖屏输入方式冲突。
3. **检查方法**：列每个任务需要同时看见的对象、可轮换查看的对象及手指遮挡区域；用最终屏幕尺寸检查，不拿编辑器放大图验收。
4. **可执行修改**：先重排区域、页签和详情，再调整画布比例；可采用缩略导航加大图详情。为需要跨文书比较的任务保存选中、位置或摘要，明确失去的同时可见性。
5. **不适用情况**：空间摆放本身决定效果时，不可自动整理成列表。Backpack Hero 的多格物品直接构成此边界。
6. **预期变化**：能读、能选，同时保留原任务所需信息；并不保证保留所有原作操作体验。
7. **验证与撤回**：在目标设备完成相同复杂任务，记录误点与反复切页；若变成依赖记忆的来回切换，恢复并列比较、摘要或暂存区。是否采用触控字号/目标尺寸应另验。
8. **来源与状态**：[S04](https://dukope.com/devlogs/papers-please/mobile/) 的作者实践，C 提供适用边界；**单个直接案例，待更多跨设备检验**。

## L3 — 给每层声明像素与文字比例，按最终输出检查

1. **触发条件**：同一图标出现粗细不一、字形发糊、缩放后边框跳动；或为了统一像素尺寸让文字小到不可读。
2. **候选解释**：非预期采样/变换、源分辨率不一致、屏幕适配与局部排版冲突。
3. **检查方法**：分别登记世界、UI框、图标、文字的源尺寸和最终倍率；看 100% 最终输出和移动过程，而非只看最近邻放大的静帧。
4. **可执行修改**：以层为单位约束比例与对齐；静态边框/图标先做整数落点；文字可采用独立可读比例。任何分层例外写入规范并附最终设备截图。
5. **不适用情况**：不把“全游戏必须同一像素大小”“所有像素游戏只能最近邻”设成审美定律；已有开发者使用混合比例与最终滤波。
6. **预期变化**：减少非预期形变并保留可读性；不是像素越粗越好。
7. **验证与撤回**：检查窗口、全屏、不同缩放与长文本；若改动只改善放大截图却降低真实阅读，撤回该层缩放。不同设备应各留基准图。
8. **来源与状态**：[S04](https://dukope.com/devlogs/papers-please/mobile/) 提供反例；具体管线检查为工程推导。**原“全局单一比例”主张撤回，替代规则待测**。
