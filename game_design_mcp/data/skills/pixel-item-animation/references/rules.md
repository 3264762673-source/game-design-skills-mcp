# 像素物品动效：条件规则卡

研究日期：2026-11-09。预期变化是待检查的预测；来源与状态限定每条规则的使用范围。执行方案由本项目综合提出，不代表所有参考作品使用了同一实现。

依据见 [来源与案例](evidence.md)。先读触发条件与例外，再采用最小可撤回修改。

## I1：将物品生命周期和结算写成契约

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 已经播拾取却没入包，入包后仍可重复拾取，开箱动画被跳过就丢奖励，或物体消失但理由不明。 |
| 候选解释 | 展示事件被误用作结算；重复触发；容量/权限拒绝没有反馈；转场或取消处理不完整。 |
| 检查方法 | 同时记录物品 ID、状态、拾取请求、接受/拒绝与库存变化；覆盖满包、多人同时请求、动画跳过、快速重按、死亡/转场/载入。单机没有的分支可以注明不适用。 |
| 可执行修改 | 最小生命周期写为“生成→掉落/就绪→请求→接受或拒绝→使用/持有→消失”；确定唯一结算权威并避免重复结算；表现监听结果，跳过或打断后仍恢复到真实物品与库存状态。 |
| 不适用情况 | 有意设计为实体飞到玩家身上才取得的玩法可以延后结算；需明示在途是否可丢失，不能假定接触瞬间就已拥有。 |
| 预期变化 | 玩家看到的取得结果与账面一致；重入/跳过不改变奖励数量。 |
| 验证与撤回 | 比较禁用动效和正常动效的结算日志；若逻辑结果不同，回退展示层对结算的依赖；不以“动画看起来对了”作为通过标准。 |
| 来源与状态 | Classic `fruit/chest`、Shovel Knight 拾取修复推导；H2补充掉落/宝箱问题。**工程候选有案例支撑；幂等方案为本文提案**。 |

## I2：让物品的等待、拒绝与成功有不同表现

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 悬浮误像正在拾取，上锁箱受击误像开箱，装备确认只闪一下却不知是否成功，悬停移开后一直发光。 |
| 候选解释 | 不同状态共用素材；循环/一次性误配； hover、focus 与确认事件混同；系统结果尚未明确。 |
| 检查方法 | 画物品状态表，对每条转换标注触发、能否取消、可交互性、结束姿态；实际比较“没资格”“接受”“已完成”能否区分。 |
| 可执行修改 | 待机用不妨碍辨识的循环；悬停/聚焦只表达可关注，不能表达已装备；拒绝回到原状态并说明原因；开箱停在真实开启状态；使用/装备以真实结果改变物体/槽位状态，随后再退掉强调。 |
| 不适用情况 | 不是所有物品都应持续浮动或发光；恐怖、伪装、探索目标允许隐藏可交互性。没有鼠标的游戏改测焦点/触控，不能强行加 hover。 |
| 预期变化 | 玩家能分辨等待、拒绝和完成，并知道下一步还能做什么。 |
| 验证与撤回 | 以任务问题检查状态判断；若新增循环干扰战斗，先改为静态就绪+事件反馈；若拒绝仍不清楚，检查文案/条件而非增加震动。 |
| 来源与状态 | Dig 作者资源目录只支持“可分离制作”的存在性；Classic 状态代码、Shovel Knight 与 H2故障记录支持逻辑边界。**美术语义部分待测，不标为跨作品视觉验证通过**。 |

## I3：为掉落/悬浮/抛掷明确谁真的在移动

| 字段 | 内容 |
| --- | --- |
| 触发条件 | 物品在画面上够得到却捡不到，浮动碰撞导致时有时无，抛掷轨迹穿墙，或载入后位置/旋转跳变。 |
| 候选解释 | 装饰偏移与实体轨迹混用；碰撞区域没同步；物理状态没有持久化；真实运动被误当纯特效。 |
| 检查方法 | 同屏显示实体位置、绘制偏移、拾取区域、速度；检查静止、落地、弹起、被击飞、吸附、停止、载入，并核对相机移动。 |
| 可执行修改 | 选择并记录三种之一：纯装饰偏移、真实轨迹物品、可破坏/材料实体。装饰循环可改绘制偏移；真实抛掷/掉落要由物理或轨迹权威驱动；落地/拾取由接触条件触发而不是屏幕坐标动画完成。 |
| 不适用情况 | Noita 类物体移动/燃烧是玩法本体，不能固定碰撞体只让图飘；反之 UI 中的装备预览无需套世界物理。 |
| 预期变化 | 视觉可达性与交互可达性更一致，保存载入不改变物品语义。 |
| 验证与撤回 | 相同初始条件对照不同帧率/暂停/载入；若变更影响原有玩法轨迹，退回物理参数，仅修绘制偏移和提示；记录允许的不确定性。 |
| 来源与状态 | Classic 悬浮与 Celeste `Throw/Drop` 作推导；H1/H2提供强边界反例。**跨案例一致的分类规则，具体动画参数待测**。 |
