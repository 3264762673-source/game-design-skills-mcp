# 组合方法与状态契约

## 来源和改编

本版读取用户本机 `grill-me` 与其实际指向的 `grilling` 定义，以及既有 `experience-theory-deconstruction`、`game-experience-transfer` 的方法与记录约定。

`grill-me` 只是调用入口。其底层 `grilling` 提供决策依赖树、按当前可回答的问题推进、事实自行查证和最后确认共识的方法。本技能以中文重新编写，加入体验论领域的问题和结构化执行代码；未打包第三方原始技能全文，也未把这些方法宣称为本项目独创。

用户体验论提供内容框架：概念的具体诠释，经由行为和反馈传达，能否形成预期共识；条件在目标载体中怎样保留或改变。设计树、版本号、自动使下游失效和 JSON 契约是本版工程化处理，不是用户原文或心理学实验结论。

沿用已有决定：目标明确时直接使用，事实可查则自己查，候选方案不以真人测试为交付前提。这里把原版“持续追问”限定于本次约定的策划范围；不会因不相干支线没有穷尽而拒绝交付草案。

## 问答字段

每个 Decision 有 `id/topic/question/recommendation/depends_on/status/answer/basis/locator`。

- `open`：尚未回答，答案与依据为空。
- `resolved`：有非空答案，依据为用户决定 `user` 或带定位的 `project_evidence`。
- `assumed`：有答案但依据是 `hypothesis`。不能因此获得已验证、用户同意或可直接实现的状态。
- 前提尚未回答时，下游保持 open。前提是 assumed 时，下游最多为 assumed。
- user 表示调用方声明来自用户，并非服务器已验证发言者。项目证据定位同样只检查是否存在文本。

## 修订和回退

一轮问题的可回答集合，在应用任何本轮答案之前计算。同轮回答父子节点被拒绝；同层独立节点可一次回答。每次答案提交产生一个新修订，保留旧、新决策记录。改父节点使所有依赖它的后代重新开放，也清除任何整份方案确认。

可返回到以前保存的完整 session 查看旧版本；不可把旧确认搬到新修订。当前模型验证会拒绝非当前修订的确认、循环依赖、未知前提、重复 ID 和“已解决节点依赖未解决节点”。历史记录用于追踪，不是签名审计日志；本地调用方可以编辑数据，本服务不提供身份认证或防篡改保证。

## 三种输出状态

| 状态 | 含义 | 接下来 |
|---|---|---|
| draft | 尚有未知/假设，或缺少默认核心章节 | 交付候选规格，列未决项 |
| awaiting_confirmation | 核心章节齐全，当前树声明的决策均解决 | 展示规格与取舍，等用户确认当前修订 |
| confirmed | 用户共识被调用方记录在当前修订 | 在原授权范围内交接实现 |

所有状态的实际体验验证仍为 `untested`，它不因问答完成自动改变。编译器不对自然语言做语义评审；AI 仍需按 SKILL.md 检查答案是否真正覆盖行为、代价、反馈和反例。

## 反例检验

例：“我想击败一个原先打不过的强敌，证明自己学会应对。”

- 若只是给角色十倍伤害，玩家操作不变，可能形成“碾压”新乐趣，不能直接认为“掌握”已迁移。
- 要检查玩家能否读出威胁并选择应对，反馈是否显示了应对为何成功。
- 用同一威胁对比有／无有效选择的情境，并让玩家不受标签暗示地描述体验；没有测试数据只记录待测假设。

示例 JSON 全为虚构演示，不代表用户已作出真实决策。
