# 像素人物设计美术：条件规则卡

研究日期：2026-11-09。预期变化是待检查的预测；来源与状态限定每条规则的使用范围。执行方案由本项目综合提出，不代表所有参考作品使用了同一实现。

依据见 [来源与案例](evidence.md)。先读触发条件与例外，再采用最小可撤回修改。

## C1 先决定玩家要辨认什么，再分配像素

- **触发条件：**人物放大单看不错，进入游戏后难找、与同类混淆，或身体过小但衣纹很多。
- **候选解释：**占屏比例不合任务；主体与邻域混在一起；身份被只在大图可见的细节承担。也可能是摄像机或界面遮挡。
- **检查方法：**记录目标显示尺寸、相机距离和任务；把人物放进真实明暗背景，在实际显示倍率检查。分别查看轮廓、主色块及完整图，指出身份线索到底在哪里。不要把缩成黑影的失败直接等同于实际画面失败。
- **可执行修改：**写「找谁/区分谁/朝哪」→先画轮廓与主要分区的候选→在至少两个实际场景并排→保留有效身份线索→再添加材质和装饰。若问题来自镜头，先调整镜头/显示预算。
- **不适用情况：**刻意匿名的人群、隐藏身份情节、无需逐个区分的单位；不要为每个群众强造唯一配色。
- **预期变化：**重要主体的定位和必要类别区分更稳定，装饰预算不再挤掉身份信息。
- **验证与撤回：**同一批背景、相同显示条件做前后任务检查；记录误认对象，而不只问「更好看吗」。若夸大轮廓改变角色性格或仍不改善定位，撤回夸大，改查局部背景或镜头。
- **来源与状态：**S04 工艺参考；S08/S09 推导；S12 检验。`case-supported`，无测得的识别率。

## C2 为身份与临时状态分配不同的视觉责任

- **触发条件：**换装备、受击或能力状态后主体像换了角色；或者身份装饰占用了需要表示状态的区域。
- **候选解释：**身份和状态在同一颜色/轮廓上反复覆盖；也可能只是状态语义未教给玩家。
- **检查方法：**建立静止、关键状态、必要装备的并排表，标出恒定线索与变化线索；看任务是否必须识别当前状态。
- **可执行修改：**先列「必须一直认出的身份」和「当前必须读出的状态」→选至少一个可保留的形状或分区关系→指定状态修改通道→为极端叠加情况画例图→再决定细节。
- **不适用情况：**变身本来就要改变身份；服装自由搭配不应被单个固定色强制限制。允许改用位置、名字等辅助身份。
- **预期变化：**状态可变而主体可追踪，减少临时效果与固定设定互相覆盖。
- **验证与撤回：**需要目标项目的状态序列和识别任务；若必要状态仍不清楚，重新分配通道，不继续堆亮度。若固定锚点妨碍变身意图，撤回该锚点要求。
- **来源与状态：**S08/S09 静态跨图只提供相容线索；S12 无状态序列。`provisional`，不可标成已跨作品验证状态因果。

## C3 先明确方向与不对称，再批量制作角色

- **触发条件：**转身后持物换手、饰物消失、脸或脚点漂移；新角色无法套用已有方向模板。
- **候选解释：**镜像规则没有声明；投影/光照不一致；基础比例与角色差异冲突。
- **检查方法：**列玩法实际使用的方向及关键姿态，对齐足点和头部范围；分开检查造型不对称与灯光方向。
- **可执行修改：**先写投影与方向需求→制作必要基础视图→标每个部件是否允许镜像→制作一个持物和一个不对称变体→检查后才批量生产。方向数由玩法决定，不固定要求 4 向或 8 向。
- **不适用情况：**纯侧视且永不转向的资产、不需物理手性的一般符号；不能为了规范增加无用方向成本。
- **预期变化：**变体与朝向的一致性可提前检查，减少后期全套返工。
- **验证与撤回：**导出一个最小角色集，在引擎逐方向切换；若统一模板限制必要体型，按共享结构拆模板，不强压比例。此执行检验本次尚未做。
- **来源与状态：**S04 主要工艺支持；S08/S09 侧视和 S12 顶视只局部相容。`provisional`，完整方向集待项目验证。
