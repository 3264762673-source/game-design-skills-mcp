## 本版的工程化处理

以下是为了稳定执行增加的组织方式，不冒充作者原话或已验证理论：

- 乐趣句、必要条件 ID、来源到目标的映射、三个独立评估状态、带版本的 JSON 记录。
- 原体验与新增乐趣分开追踪；实际效果状态必须有相关人类体验反馈才能更新。
- 明确区分角色知情与玩家知情；只列与本次乐趣有关的条件。
- 补充理论按具体问题加载；既有两个配套技能是可选工具，不是安装依赖。
- 新增“寻宝贪念”虚构案例，用来展示可执行迁移与可否定假设。
