# 系统设计决策卡

下列方案用于形成可测试的决定。来源 S 编号见 [来源与状态](source-map.md)。每次只选择与当前证据相符的卡片。

<a id="sys-01"></a>
## SYS-01 把概念转成可推演系统

**触发条件**：设计描述只有题材、情绪和功能列表；团队无法对同一段玩家操作推演出一致结果。

**候选解释**：关键对象或状态未定义；行动的前置条件、状态变化或相互关系缺失；也可能只是描述精度尚未进入制作阶段。

**检查方法**：选择一段代表性操作，列出初始状态、输入、允许条件、状态变化、可见结果和后续可用行动。由两名参与者独立推演，记录分歧及依赖的隐含规则。随机结果用概率或可达状态集合描述。

**可执行修改**：只补齐造成分歧的规则及状态。用“行动 → 判定 → 状态变化 → 玩家可见结果 → 下一步”描述最小循环；先让该段过程可运行或可纸面推演，再扩展内容。

**不适用情况**：早期自由发散尚未要求落地；或已有清楚模型，问题实际是实现错误、数值或内容表达。

**预期变化**：同一条件下的推演分歧减少，原型能完整走通这段过程。该变化只说明系统定义更清楚，不直接证明更有趣。

**验证与撤回**：使用原先产生分歧的情景复验，再加入一个边界情景。确定规则应得到一致结果，随机规则应得到一致的可能结果与概率说明；若新增规则制造未解决矛盾或没有服务目标体验，撤回该规则并保留问题记录。

**来源与状态**：S03（P112，D）的系统要素、关系与情境；具体推演表与判定是工程推导；待测。

最小模型只填写实际需要的项：

| 项 | 应记录的内容 |
|---|---|
| 情境 | 谁参与，何时开始／结束，哪些规则生效 |
| 对象与状态 | 玩家、可交互对象、资源，以及影响当前过程的状态 |
| 行动与判定 | 可以做什么、允许条件、随机性或其他参与者影响 |
| 转移与观察 | 哪些状态改变，玩家能看到哪些部分 |
| 目标与后续 | 局部成果、失败／退出条件，以及下一步行动 |

<a id="sys-02"></a>
## SYS-02 区分规则难懂与规则执行不一致

**触发条件**：玩家反复尝试同一操作，或无法解释为什么这次成功、上次失败；团队对合法行动有不同说法。

**候选解释**：隐藏前置条件不清楚；反馈没说明拒绝原因；实际状态不同；随机性或秘密信息符合设计意图；也可能是实现缺陷。

**检查方法**：对比输入、前置状态、判定路径与结果。让玩家在揭示结果前预测“能否执行及为什么”；隐藏信息任务只要求识别可知条件及不确定范围，不要求猜中秘密或随机结果。

**可执行修改**：执行错误交给技术修复；规则稳定但理解困难时，补上必要的条件提示、状态标记或明确拒绝原因。只有规则本身造成无价值歧义时才修改规则。

**不适用情况**：玩家理解规则但技术操作失败；规则探索、悬念或信息博弈就是体验目标，且未知范围符合事先约定。

**预期变化**：可知条件下的合法行动预测更准确，因误解规则产生的无效尝试减少；保留设计需要的不确定性。

**验证与撤回**：固定条件比较预测和实际判定，记录正确次数／可判断次数，以及错误原因。若提示泄露策略、使发现乐趣消失或降低原定信息博弈质量，撤回或缩小提示范围。不要用降低整体难度代替理解度验证。

**来源与状态**：S06（P115，G）关于规则界定行动与结果，辅以 S03；预测任务和日志对照为工程推导；待测。

<a id="sys-03"></a>
## SYS-03 区分有意挑战与无关摩擦

**触发条件**：玩家长时间停滞、等待或重复操作；设计者把所有困难都称为“挑战”，却说不清它训练或要求什么。

**候选解释**：阻力正是目标体验的一部分；信息或操作负担掩盖了真正挑战；能力与任务不匹配；也可能存在技术延迟或内容不足。

**检查方法**：先写明希望玩家运用的能力，如判断路线、分配资源、执行时机、合作或解题。把一次失败拆成决策、执行、等待和恢复，定位消耗时间或造成错误的环节；询问玩家失败时正在尝试什么。

**可执行修改**：保留服务目标能力的阻力，优先减少无关步骤。例如让失败后更快回到练习点，或清晰表达已有约束；如果核心选择缺乏阻力，再原型验证一个与目标相符的限制。

**不适用情况**：仪式、慢节奏、耐心或重复本就是目标体验；玩家仅表示“不想玩这一类”。不能据此自动加敌人、计时器、资源惩罚或更多难度。

**预期变化**：玩家把更多时间用于目标活动，能更准确解释失败原因；同时保留原定挑战和节奏。

**验证与撤回**：在同一挑战配置下记录目标活动时间／任务观察时间、恢复耗时及失败原因。成功率上升只是辅助信息；若改动消除了所需取舍、破坏节奏或让玩家更难理解失败，撤回。比例没有通用达标线，应结合体验目标预先约定。

**来源与状态**：S02（P111）自愿接受约束与 S05（P114，F）多种冲突形式；“摩擦分解”及度量为工程推导；待测。

<a id="sys-04"></a>
## SYS-04 让阶段成果能够被判断

**触发条件**：目标导向玩法中，玩家不知道还差什么、何时完成，或无法解释结算为什么成功／失败。

**候选解释**：目标条件未定义；进展不明确；系统判定与玩家理解不一致；也可能是开放式体验被错误地要求有终局。

**检查方法**：询问玩家当前目标及判断完成的方法；将回答与实际规则逐项对照。检查成功、失败、部分完成、退出、同时触发条件及临界值如何处理。

**可执行修改**：将任务落实为可判断状态，并呈现必要进展与结算理由。已完成的局部目标要有明确状态；开放式创造优先提供作品状态、保存结果或用户自定目标，不强加全局胜负。

**不适用情况**：纯探索、表达或自由游玩并不需要规定终点；未知目标是经过设计的发现过程。可判定结果也不要求一定展示分数。

**预期变化**：玩家能更准确判断阶段是否完成、为什么完成，以及下一步可以做什么。

**验证与撤回**：用接近完成、刚好完成、失败和退出等实际适用情景，比较玩家判断与系统判定；同时记录是否损害探索或自定目标。若提示提前揭示内容、把开放体验变成清单任务，撤回或改为按需显示。

**来源与状态**：S06（P115，G）的可判定结果；S01/S08（P109/P118）的定义边界。局部目标与开放式适配属于工程推导；待测。
