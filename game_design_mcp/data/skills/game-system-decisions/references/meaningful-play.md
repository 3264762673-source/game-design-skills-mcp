# 行动与体验决策卡

讲义 P117 区分两件事：行动结果能被辨识，以及结果与整体过程有联系。以下进一步拆成可排查的问题；来源见 [来源与状态](source-map.md)。

<a id="play-01"></a>
## PLAY-01 确认行动结果是否可辨识

**触发条件**：玩家重复输入、误以为操作没有成功，或在已成功之后仍寻找确认。

**候选解释**：输入未到达或被拒绝；输入已接受但结果不可见；反馈对象不明确；处理延迟；玩家已理解结果但不知道下一步。

**检查方法**：对齐输入记录、接受／拒绝判定、状态变化与录像。让玩家说明“刚才发生了什么”。分别检查请求已接收、处理中、完成这几个实际存在的阶段；不能把“已接收”画成“已完成”。

**可执行修改**：若事件未接受，先解决输入或判定问题；若已接受但不可辨识，在受影响对象上显示状态变化，必要时补充处理进度或拒绝原因。选择最少且足够的视觉、声音或触觉提示。

**不适用情况**：玩家清楚结果，困难在下一步目标；或延迟揭示就是机制的一部分。后者只确认允许公开的信息，保留设计需要的未知。

**预期变化**：同类情景中的重复无效输入减少，结果识别更准确，正确进入下一步的比例提高。

**验证与撤回**：预先定义何为重复无效输入及观察窗口，区分连击、蓄力和合法高频输入。记录无效重复次数／相关操作次数、结果识别、进入下一步情况，并检查遮挡与干扰。若无改善或提示遮住目标、混淆成功与处理中，撤回该提示。

**来源与状态**：S07（P117，I）的可辨识性；输入链路排查和指标为工程推导。结构与案例方向也参考用户截图；待测。

<a id="play-02"></a>
## PLAY-02 检查结果是否进入后续玩法

**触发条件**：玩家知道操作成功，却觉得行动只是“亮一下”“领一次”，随后玩起来没有区别。

**候选解释**：状态没有真正改变；改变被立即覆盖或重置；影响存在但未被理解；关联太远或太弱；也可能该行动本就服务即时表达或感官体验。

**检查方法**：追踪“行动 → 状态差异 → 后续可用行动／约束／目标变化”。在其他条件相同的可比状态下，检查执行与不执行该行动的后续区别；再询问玩家能否指出这种联系。

**可执行修改**：有影响但不可理解时，补充因果线索或适当的结果回顾；确实没有影响且目标要求系统性后果时，让已有状态影响一个相关的后续条件。优先使用现有机制，避免自动加入永久成长、稀有度或奖励货币。

**不适用情况**：拍照、装扮、自由表达、音乐演奏等行动的目标可以是当下表达；延迟影响也可能符合体验意图。不能要求每次动作都改变长期进程。

**预期变化**：目标行动在后续状态中产生可说明的区别，玩家对因果的判断更准确；不以奖励数量增加作为有效证明。

**验证与撤回**：在变化应发挥作用的时间范围内复验后续状态与玩家理解，记录影响是否实际发生及是否被正确归因。若产生无关复杂度、累积优势失控或让行动变成强制劳动，撤回或缩小作用范围。

**来源与状态**：S07（P117，I）的整合性；状态对照、因果提示与撤回条件为工程推导；待测。

<a id="play-03"></a>
## PLAY-03 检查选择是否服务预期体验

**触发条件**：设计目标要求策略取舍，但玩家认为多个选项只是换名字，或在所有目标情景下都选同一个。

**候选解释**：结果等价；存在支配选项；成本和后果读不懂；任务情景过窄；玩家偏好稳定；选项的价值本来就在表达或角色扮演。

**检查方法**：在几个具有实质差异的状态下，列出选项的成本、立即结果和后续影响；询问选择理由，而不是只统计选择分布。检查玩家是否理解差异及差异是否真能发生。

**可执行修改**：不理解差异时先改善表达；理解后仍与策略目标不符时，原型验证一个与现有系统相关的情景取舍。对表达性选择，验证表达是否到位，不强加效率差异。

**不适用情况**：外观偏好、角色扮演或简化体验不以策略深度为目标；稳定选择本身不是缺陷。无需强迫每个选项被同样多的人选择。

**预期变化**：在目标需要的情景中，玩家能说明选择依据，并根据相关状态调整行动；保留可理解性与原有体验方向。

**验证与撤回**：固定可比情景，记录理解、理由、选择及后续结果。用“是否出现符合意图的情景取舍”判断，不用选项分布均匀度代替质量。若只增加计算负担、破坏表达或形成新的支配选项，撤回并重新定位原因。

**来源与状态**：S07（P117，I）提供行动与整体后果的概念；本卡对“选择质量”的应用是进一步工程假设，讲义没有直接证明。待测。

## BOUND-01 检查参与约定与现实边界

**触发条件**：玩家对计分、角色权限、退出后果或模拟／真实影响有不同预期，导致行为误解或参与争议。

**候选解释**：进入时的约定不清楚；规则在途中变化；系统呈现与实际权限不一致；游戏中的代币、身份或动作被误认为没有现实影响；也可能是正常的策略欺骗或角色扮演。

**检查方法**：记录进入、关键操作、退出三个环节的实际规则，让参与者分别说明何时生效、哪些信息可隐藏、什么会被保存或影响他人。将说法与实际行为对照；只检查当前产品确实涉及的影响。

**可执行修改**：在相应决策点明确生效范围、角色权限、可逆性与退出结果；把模拟状态和真实操作清楚区分。允许博弈中的隐瞒，但让参与者理解隐瞒属于怎样的玩法约定。

**不适用情况**：参与者理解并接受既定规则，争议只是输赢或偏好差异；不应为此泄露秘密身份、隐藏资源等机制信息。

**预期变化**：对关键约定的理解更一致，因边界误解而产生的操作、意外损失或争议减少，同时保留目标体验。

**验证与撤回**：在安全的演示情景检查进入／退出及关键操作的预测；真实争议数据应明确暴露次数和情景。若提示仅增加打断，可调整时机或表达；如果涉及必须保留的实际权限与后果披露，撤回的是无效呈现方式，不是必要信息。

**来源与状态**：S02/S04（P110–P111、P113、P116）的参与和约定边界；S09（P153–P154）提醒边界可被质疑。具体操作与验证为工程推导；待测。
