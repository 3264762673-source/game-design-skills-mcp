# 决策验证记录

只在需要记录设计改动的效果时使用。空白项表示尚未记录；它们不是可以由 AI 自行虚构的结果。

## 改动前

| 项目 | 填写内容 |
|---|---|
| 项目与版本 | 基线版本、候选版本、改动位置及撤回方法 |
| 目标体验 | 希望保留或改善的玩家活动 |
| 观察 | 情景、行为、输入／状态记录、录像时间点或访谈摘记 |
| 证据边界 | 哪些已观察，哪些只是推断 |
| 卡片与来源 | 决策卡 ID、讲义 S 编号及段落 |
| 主假设与替代解释 | 为什么怀疑该原因，什么结果会推翻它 |
| 最小改动 | 一项能区分解释的改动，或说明必须联动的原因 |
| 预期行为 | 谁在什么状态下会发生什么可观察变化 |
| 计数口径 | 分子、分母、观察窗口、有效样本和排除条件 |
| 保留与撤回依据 | 预先定义方向、项目目标及不可接受副作用 |

## 测试条件

记录目标玩家特征、实际人数或次数、任务、难度、设备、输入方式及可用的随机种子。注明这些条件与预期使用者的差异。

- 原型或规则测试：可验证状态转移、条件与结果，不证明玩家理解或乐趣。
- 录像和日志：可验证行为与时序，单独使用时通常不能确定动机。
- 真人试玩与解释任务：用于观察理解和体验；保留原始理由，避免诱导提问。
- 自己或 AI 推演：仅作为检查假设或发现矛盾的线索，不计作目标玩家试玩。

比较前后版本时记录练习效应、版本顺序、外部提示与其他同时变化。必要时交错版本顺序或使用不同参与者；不要把不同难度、内容量或设备造成的变化归于当前改动。

## 测试后

| 项目 | 填写内容 |
|---|---|
| 实际样本与结果 | 展示原始次数及比例；无数据写“未测试” |
| 替代解释 | 哪些仍不能排除 |
| 副作用 | 遮挡、节奏、策略、表达、疲劳等实际相关影响 |
| 决定 | 保留／继续观察／撤回，及对应理由 |
| 状态 | 待测／初步支持／不支持／不确定／项目内复验 |
| 有效范围 | 适用于哪个版本、玩家、任务和条件 |
| 下一步 | 需要的最小追加证据，或已完成的撤回记录 |

没有通用样本数、达标百分比或“乐趣分数”。小样本结果写成条件化观察；若要对群体效果作强结论，需要另外设计足够的研究。

## 示例计数口径

PLAY-01 可以把一次操作机会定义为“可交互对象出现到玩家正确进入下一状态”。仅把第一次请求已经接收后、没有设计意义的再次输入记为重复；排除合法连击。报告“重复发生的操作机会数／全部有效操作机会数”，并单独记录结果识别情况。

这是一种工程示例，不是标准时间窗口或实测结果；应按具体游戏机制调整。
