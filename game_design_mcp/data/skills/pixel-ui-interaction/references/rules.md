# 像素 UI 页面交互：条件规则卡

研究日期：2026-11-09。预期变化是待检查的预测；来源与状态限定每条规则的使用范围。执行方案由本项目综合提出，不代表所有参考作品使用了同一实现。

依据见 [来源与案例](evidence.md)。先读触发条件与例外，再采用最小可撤回修改。

## X1 — 每次页面/模式转换都定义焦点所有者和返回位置

1. **触发条件**：开背包后角色继续移动；关弹窗后失去选中项；同一输入因隐蔽模式触发另一动作。
2. **候选解释**：输入未由当前模式消费、隐藏控件残留焦点、返回目标已删除或模式变化没有表现。
3. **检查方法**：写状态表：状态→允许输入→转移→当前焦点→退出后焦点；逐条走打开、确认、取消、关闭、对象删除和切设备路径。
4. **可执行修改**：模态层取得自己的输入上下文；记录来源控件，关闭后恢复至仍存在的来源或明确兜底项；让模式入口、当前工具、退出方式可见。游戏内拖拽模式与设置菜单可使用不同规则，但各自应明确。
5. **不适用情况**：无焦点指针界面不必强造手柄焦点；游戏刻意的模式谜题需另定理解目标。不能把所有模式都改成阻断游戏的弹窗。
6. **预期变化**：取消/返回后可继续原任务；减少误触背景与焦点丢失。
7. **验证与撤回**：做嵌套弹窗、长列表滚动、选中物品被消耗等序列测试。若恢复旧对象已无效，改到可预期邻项而非随机首页。输入日志存在穿透则先修逻辑，不能靠动画遮盖。
8. **来源与状态**：[S04](https://dukope.com/devlogs/papers-please/mobile/) 支持局部模式实践；[S14](https://docs.godotengine.org/en/stable/tutorials/ui/gui_navigation.html) 说明隐藏控件会失焦及初始焦点配置。**案例仅部分支持，状态机规则是待测工程推导**。

## X2 — 当选择依赖后果时，让对象、成本与预期结果可检查

1. **触发条件**：玩家无法区分选择对象、预览行动与最终提交；或者只有提交后才知道原本应能得知的代价。
2. **候选解释**：信息缺失、预览对象错位、确认边界隐蔽；也可能是游戏有意保留不确定性。
3. **检查方法**：先由玩法规格说明哪些信息应已知；对照“当前对象→行动→成本→结果/未知范围”，检查界面是否错误暗示确定性。
4. **可执行修改**：把可知信息放在对象说明、范围/方向标记、成本提示中；预览与最终提交使用可区分状态。是否支持撤销由玩法决定，支持时明确撤销边界。
5. **不适用情况**：推理、赌博或隐藏信息玩法不能被 UI 自动揭底；具有节奏/责任感的盖章、出牌不能一律自动化或无代价回退。
6. **预期变化**：减少“以为点了另一对象/没想到要花这个”的误用，同时保留设计允许的不确定性。
7. **验证与撤回**：让测试者在提交前说明将发生什么，并区分故意未知；若提示剧透解题或撤销破坏资源压力，收窄到操作确认，不改玩法信息规则。
8. **来源与状态**：[S02](https://media.gdcvault.com/gdc2019/presentations/Into%20the%20Breach%20Postmortem%20Final.pdf)、[S04](https://dukope.com/devlogs/papers-please/mobile/)、[S10](https://store.steampowered.com/app/1970580/Backpack_Hero/) 支持不同情境。**收窄后有案例支持；“所有后果都预告/所有操作可撤销”撤回**。

## X3 — 针对承诺支持的输入方式验证完整任务，而非只显示对应按键图

1. **触发条件**：游戏标称手柄或键盘支持，但菜单有只有 hover 才能出现的说明、不可达关闭按钮或导航死路。
2. **候选解释**：焦点邻接自动猜测不符布局、默认焦点缺失、绑定只覆盖主流程、输入提示没有随模式改变。
3. **检查方法**：从首次启动到设置、开局、库存、确认、取消及退出，用每一种承诺支持的输入单独完成；记录不可达控件和需要借用其他设备的步骤。
4. **可执行修改**：明确初始焦点、方向邻接及 Tab 顺序；统一确认/返回语义；给 hover 信息提供 focus/按键/触控替代路径；状态变动时维护邻接与滚动可见性。输入动词可一致，手势实现可以不同。
5. **不适用情况**：未承诺某设备不等于必须实现它；但一旦承诺，应明确哪些玩法环节有限制。地图或空间拼图不能硬套线性表单导航而破坏方向关系。
6. **预期变化**：单一输入能完成所承诺的全部核心任务，且返回/选择含义稳定。
7. **验证与撤回**：断开鼠标做键盘/手柄测试，反向测试触摸；加入列表为空、物品删除、弹窗关闭情况。若自动邻接跳跃，改显式邻接；不要以“商店有手柄标签”代替验证。
8. **来源与状态**：[S07](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112)、[S14](https://docs.godotengine.org/en/stable/tutorials/ui/gui_navigation.html)。C 商店声明不能验证行为；**工程要求，跨作品运行测试尚未完成**。
