# 方法来源与使用边界

编制日期：2026-10-30。该技能是用户体验论的参考作品拆解版本；既有 game-experience-transfer 聚焦迁移和乐趣记录，本技能增加来源研究和拆解环节，不覆盖旧技能。

## 用户方法

本轮读取工作区既有《冷启动：系统层级论+体验论.txt》，位于 `local-source-not-distributed`；并读取既有技能 `game-experience-transfer/references/sources-and-decisions.md` 与 `pleasure-model.md`。

核心是“体验的迁移源自于对概念的诠释的共识”。游戏用符号、行为和结果赋予概念含义；玩家能否理解该含义决定迁移是否有机会成立。技能中的因果链、条件 ID 和实验记录是工程化整理，不是用户原文或已验证心理模型。

遵循既有技能记载的后续决定：明确目标直接沿用，必要条件带假设继续，真人试玩不作为交付前置。原始材料的停线指令、七/八项动机、层级和封装数字存在历史分歧，不能不加区分地重新引入。

## 完整案例应怎样写

以动作游戏为例，候选体验为“我看懂一个有威胁的对手，通过自己的应对夺回主动权”。

- 强敌：会阻挡、抢回合并惩罚失误；不是单纯血厚。
- 掌握：相同威胁下，玩家能重复做出有理由的选择；不是角色替玩家表演。
- 打击：接触之后，对象状态发生可信变化；不是只看到亮光。
- 释放：紧张之后出现短暂优势；全程同强度反馈会消解对比。

迁移到网页时可缩减场景与敌人数，但若删掉抵抗、风险和选择，仅保留连击演出，应记为“动作观赏/碾压”新体验，原目标尚未迁移。

## 记录最少字段

记录目标原文、版本、来源和阅读范围、体验句、条件 ID、目标规则、反馈、反例、迁移状态、新乐趣状态、下一次实验。修订时保留“旧诠释 → 新诠释 → 修改理由”，防止事后重定义把失败变成成功。
